# Deployment Guide

Step-by-step guide for installing service-controller on a production Linux server.

> **TL;DR** — copy files to `/opt/service-controller/`, generate sudoers, run as a systemd service under an unprivileged user `service-controller`, put Caddy + PocketID in front. Never expose the Flask port directly to the internet.

## 1. Pre-installation checks

### 1.1 Python version

service-controller requires **Python 3.9+** (uses `pathlib`, `asyncio` patterns).

```bash
python3 --version
# Confirm it is 3.9 or newer
```

### 1.2 System user

Create a dedicated unprivileged user to run the app and sudoers. See
section 3.1 for the exact command:

```bash
sudo useradd --system --no-create-home --shell /usr/sbin/nologin service-controller
```

The user needs:
- read access to `/opt/service-controller` and the venv
- passwordless `sudo` access to `systemctl start/stop/restart <unit>`
  only for units listed in `services.json`

### 1.3 Sudo

If any `systemctl` calls must run as root, the app user needs a
`NOPASSWD:` sudoers entry covering exactly the configured units. Do
NOT grant blanket `systemctl` access — only generate the policy with
`scripts/gen_sudoers.py` (see §3).

### 1.4 systemd

service-controller only manages other services on **the same host** via
`systemctl`. If you ever want to manage remote units, that is out of
scope and must be done with a different tool (Tailscale, VPN, etc.).

## 2. Production installation

### 2.1 Install with `install.sh`

```bash
sudo bash install.sh
```

This performs the entire flow:

1. Create user `service-controller` (if not present).
2. Create `/opt/service-controller/`.
3. Copy project files (`app.py`, `services.py`, `templates/`,
   `static/`, `scripts/`, `service-controller.service`,
   `scripts/gen_sudoers.py`, `install.sh`) into place.
4. Generate `services.json` from `services.example.json` if none
   exists.
5. Generate `service-controller.env` with sensible defaults if
   missing.
6. Create a Python venv and install Flask.
7. Set ownership and permissions on the `/opt/service-controller` tree.
8. Generate the sudoers file from the new `services.json` and
   validate it with `visudo -c -f`. (Do **not** auto-install it — it
   must be reviewed and placed manually if the generated policy
   differs from what you want.)

### 2.2 Manual step-by-step

If you prefer to do it manually:

```bash
# 1. Create user (if missing)
sudo useradd --system --no-create-home --shell /usr/sbin/nologin service-controller

# 2. Create install dir
sudo mkdir -p /opt/service-controller

# 3. Copy project files
sudo cp -r app.py services.py templates static scripts service-controller.service \
              scripts/gen_sudoers.py /opt/service-controller/

# 4. Create services.json from example
sudo cp /opt/service-controller/services.example.json /opt/service-controller/services.json
# Edit /opt/service-controller/services.json with your real unit names

# 5. Create service-controller.env if missing
cat > /opt/service-controller/service-controller.env <<EOF
# Auto-generated by install.sh. Edit to override.
: ${SERVICES_CONFIG:=/opt/service-controller/services.json}
: ${HOST:=127.0.0.1}
: ${PORT:=8090}
: ${SYSTEMD_SERVICES:=}
: ${SYSTEMD_SERVICE:=}
EOF

# 6. Create venv and install Flask
sudo python3 -m venv /opt/service-controller/venv
sudo /opt/service-controller/venv/bin/pip install flask

# 7. Set ownership
sudo chown -R service-controller:service-controller /opt/service-controller
```

> **`install.sh` vs manual**: For non-standard setups you may want to
> hand-edit paths, but `install.sh` is hard-coded for this layout.

## 3. Generate sudoers

`scripts/gen_sudoers.py` reads the same config as the app and prints a
sudoers snippet in lockstep with it.

```bash
cd /opt/service-controller
python3 scripts/gen_sudoers.py --user service-controller
```

The script resolves `services.json` → `SYSTEMD_SERVICES` →
`SYSTEMD_SERVICE` → `llama-server.service` — the same order as the
app itself (see `services.py` lines 15–30).

### Sample output

```text
# sudoers — generated for 5 service(s)

Cmnd_Alias SVC_CTL_LLAMA_GPX = /usr/bin/systemctl start llama-gpx.service, /usr/bin/systemctl stop llama-gpx.service, /usr/bin/systemctl restart llama-gpx.service
Cmnd_Alias SVC_CTL_STABLEDIFF = /usr/bin/systemctl start stable-diffusion.service, /usr/bin/systemctl stop stable-diffusion.service, /usr/bin/systemctl restart stable-diffusion.service

service-controller ALL=(root) NOPASSWD: SVC_CTL_LLAMA_GPX, SVC_CTL_STABLEDIFF
```

Each alias is scoped to one unit only; the user line grants
passwordless `systemctl {start,stop,restart} <unit>` for every
configured unit.

## 4. Install and harden sudo policy

1. Generate and review:

   ```bash
   cd /opt/service-controller
   python3 scripts/gen_sudoers.py --user service-controller > \
       /tmp/service-controller-sudoers
   ```

2. Validate syntax **before** installing:

   ```bash
   sudo visudo -c -f /tmp/service-controller-sudoers
   ```

3. Place somewhere `visudo` will pick up (note: `visudo -c` must pass
   or your sudo installation is broken):

   ```bash
   sudo cp /tmp/service-controller-sudoers /etc/sudoers.d/service-controller
   sudo chmod 0440 /etc/sudoers.d/service-controller
   ```

4. Confirm the policy as seen by the user:

   ```bash
   sudo -l -U service-controller | head -20
   ```

5. Test run as the service user:

   ```bash
   sudo -u service-controller -H -s
   /opt/service-controller/venv/bin/python \
       -c "from services import load_services; print(load_services())"
   systemctl start <any-configured-unit>
   ```

### Hardening

- The unit never grants `systemctl daemon-reload`, `systemctl restart
  *`, or `systemctl status` — only `start`, `stop`, and `restart` of
  exact units.
- `NOPASSWD` is required because the Flask app cannot supply a
  password non-interactively.
- Every alias is unit-scoped. Adding a service means editing
  `services.json` and re-running the sudoers generator.

## 5. Reverse proxy (Caddy)

The Flask app binds to `127.0.0.1:8090` by default — **not** to the
LAN or internet. Put Caddy in front for authentication and routing.

### 5.1 Caddyfile site block

```caddyfile
service-controller.example.com {
    reverse_proxy 127.0.0.1:8090
}
```

Adjust the site block hostname to match your real domain. Caddy
itself will handle TLS (`Caddyfile` auto-issues certificates, see
https://caddyserver.com ).

### 5.2 Adding PocketID forward_auth

If you already forward-auth a domain with PocketID and want to
re-use that for service-controller, append `forward_auth` to the
existing site block:

```caddyfile
service-controller.example.com {
    forward_auth login.example.com {
        uri /api/verify
        copy_headers Remote-User Remote-Email
    }
    reverse_proxy 127.0.0.1:8090
}
```

> If there is no pre-existing PocketID instance, you can deploy a
> PocketID server in a Docker container instead of trying to patch
> the site block. See PocketID docs for details.

### 5.3 Restrict access by IP (optional)

If PocketID isn't available, lock down via Caddy's `respond` matcher
for trusted LAN subnets only:

```caddyfile
service-controller.example.com {
    respond "forbidden" 403 {
        @private ip 10.0.0.0/8 192.168.0.0/16 172.16.0.0/12
    }
    reverse_proxy 127.0.0.1:8090
}
```

### 5.4 Why no direct 0.0.0.0?

`app.py` binds to `127.0.0.1` by default. If you accidentally
`--bind 0.0.0.0` it, anyone on your network can stop and start any
configured service. Caddy handles auth, TLS, and request logging.

## 6. Enable the systemd service

### 6.1 Install the unit

```bash
sudo cp /opt/service-controller/service-controller.service \
        /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now service-controller.service
```

### 6.2 Verify

```bash
sudo systemctl status service-controller.service
# Active: active (running)
```

Logs:

```bash
sudo journalctl -eu service-controller.service --follow
```

## 7. Adding services

### 7.1 JSON configuration

Edit `/opt/service-controller/services.json` in-place:

```bash
sudoedit /opt/service-controller/services.json
```

```json
[
  {"id": "fastflowlm-npu",
   "unit": "flm.service",
   "label": "StrixHalo FastFlowLM Gemma (NPU)"},
  {"id": "llama-gpu-l",
   "unit": "llama-cpp-l.service",
   "label": "llama Laguna (GPU)"},
  {"id": "llama-gpu-m",
   "unit": "llama-cpp-m.service",
   "label": "llama Mistral (GPU)"},
  {"id": "llama-gpu-q",
   "unit": "llama-cpp-q.service",
   "label": "llama Qwen (GPU)"}
]
```

Only `unit` is required. `id` is derived from `unit` if omitted
(see `services.py:_slugify`). `label` is auto-generated if
omitted (see `services.py:_titleize`).

> See `services.py` lines 40–76 for the exact slugify/titleize
> rules. Every unit is regex-validated against `^[A-Za-z0-9@_.\-]+\.service$`.

### 7.2 Re-scope sudo

Every time `services.json` changes you re-generate sudoers:

```bash
cd /opt/service-controller
python3 scripts/gen_sudoers.py --user service-controller > \
    /tmp/service-controller-sudoers
sudo visudo -c -f /tmp/service-controller-sudoers
sudo cp /tmp/service-controller-sudoers /etc/sudoers.d/service-controller
sudo systemctl restart service-controller.service
```

Not doing this means newly added services show in the UI but their
start/stop/restart calls fail with a sudoers `forbidden command`
error.

### 7.3 Adding a systemd unit to manage (not yet covered)

If you want to actually manage a third-party systemd service, add a
"[Unit]" section to its `.service` file under `/etc/systemd/system/`
or `/lib/systemd/system/` — that is outside the scope of this guide.

## 8. Configuration reference

### 8.1 Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `SERVICES_CONFIG` | `/opt/service-controller/services.json` | Path to the JSON file that lists controlled services; see `services.py:_raw_entries`. |
| `HOST` | `127.0.0.1` | Flask bind address. |
| `PORT` | `8090` | Flask bind port. |
| `SYSTEMD_SERVICES` | `""` | Comma-separated list of unit names, overrides `SERVICES_CONFIG` if set. See `services.py:_raw_entries` line 27. This is the recommended way to declare services outside of `services.json`. |
| `SYSTEMD_SERVICE` | `""` | Legacy single-service name, falls through if `SYSTEMD_SERVICES` is empty. See `services.py:_raw_entries` line 31. |

Note: only one of the three (`SERVICES_CONFIG`, `SYSTEMD_SERVICES`,
`SYSTEMD_SERVICE`) can win; order is exactly as listed.

### 8.2 File layout under `/opt/service-controller/`

```
/opt/service-controller/
├── app.py                            # Flask app, no external imports outside venv
├── scripts/
│   └── gen_sudoers.py                # Generates sudoers rule from current config
├── service-controller.env            # Defaults, edited by install.sh
├── service-controller.service        # Systemd unit file (copied to /etc/systemd/system/)
├── services.example.json             # Example config — not used in production
├── static/
│   ├── app.js                        # Frontend JS (panels, polling, buttons)
│   └── style.css                     # UI styles
├── templates/
│   └── index.html                    # Jinja2 template; one panel per service
└── venv/                             # Python venv + flask
```

## 9. systemd unit reference

File: `/etc/systemd/system/service-controller.service`
Source: `service-controller.service` (copied by install.sh or manually;
the source file lives in the project root at `/home/la_lukasz/Code/service-controller/service-controller.service`).

```ini
[Unit]
Description=service-controller web UI
After=network.target

[Service]
Type=simple
User=service-controller
Group=service-controller
WorkingDirectory=/opt/service-controller
Environment=SYSTEMD_SERVICE=llama-server.service
Environment=HOST=127.0.0.1
Environment=PORT=8090
ExecStart=/opt/service-controller/venv/bin/python /opt/service-controller/app.py
Restart=on-failure
RestartSec=3

# Light hardening — adjust if it conflicts with your sudoers/systemctl setup
NoNewPrivileges=false
ProtectSystem=strict
ReadWritePaths=/opt/service-controller
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

### Sections documented

| Section | Directive | Default | Meaning |
|---|---|---|---|
| `[Unit]` | `Description` | `service-controller web UI` | shown in `systemctl status` |
| | `After=network.target` | — | start after network is up |
| `[Service]` | `Type` | `simple` | single-process foreground Flask app |
| | `User` / `Group` | `service-controller` | unprivileged user; no shared credentials with root |
| | `WorkingDirectory` | `/opt/service-controller` | where `services.py` resolves relative paths |
| | `Environment` | `HOST=127.0.0.1`, `PORT=8090`, `SYSTEMD_SERVICE=llama-server.service` | overridden in `service-controller.env` if generated |
| | `ExecStart` | `/opt/service-controller/venv/bin/python /opt/service-controller/app.py` | absolute path ensures the venv is used regardless of PATH |
| | `Restart=on-failure` | — | auto-restart on crash, not on clean exits |
| | `RestartSec=3` | — | wait 3s between attempts |
| | `NoNewPrivileges=false` | — | permit the process's `sudo` to actually elevate (required for `systemctl` calls) |
| | `ProtectSystem=strict` | — | `/usr`, `/boot`, `/etc` read-only to the service |
| | `ReadWritePaths=/opt/service-controller` | — | whitelist the install dir for venv writes |
| | `PrivateTmp=true` | — | container-style `/tmp` isolation |
| `[Install]` | `WantedBy=multi-user.target` | — | start on normal multi-user boot |

### Environments override

`systemctl` env directives from `service-controller.env`:

```bash
sudo systemctl set-environment SERVICES_CONFIG=/opt/custom/services.json HOST=0.0.0.0 PORT=8091
sudo systemctl daemon-reload
sudo systemctl restart service-controller.service
```

## 10. Troubleshooting

### 10.1 `sudoers: user service-controller not allowed on host`

The sudoers file wasn't installed. Run §3 again and reinstall to
`/etc/sudoers.d/service-controller`. Check `sudo -l -U service-controller` to
see the effective policy.

### 10.2 `Permission denied` in Flask logs

`chmod 0640` the `services.json` file (or make the whole `/opt/service-controller`
readable by the user):

```bash
sudo chown -R service-controller:service-controller /opt/service-controller
sudo chmod 0640 /opt/service-controller/services.json
sudo chmod 0750 /opt/service-controller    # restrict directory listing
```

### 10.3 Service UI shows one service but Flask can't start it

`gen_sudoers.py` must be run and installed every time `services.json`
changes. Otherwise the running app thinks the service is there but
`sudopy` refuses to start it. Always restart `service-controller.service`
_after_ installing the new sudoers file:

```bash
sudo cp /tmp/service-controller-sudoers /etc/sudoers.d/service-controller
sudo systemctl restart service-controller.service
```

### 10.4 `ERROR: 'module' object has no attribute 'load_services'`

The app is running from the system Python `python3` instead of the
venv's `python`. `app.py`'s shebang requires only `python3` — but the
service runs `/opt/service-controller/venv/bin/python`. If you ever
need to debug by hand, invoke:

```bash
/opt/service-controller/venv/bin/python /opt/service-controller/app.py
```

### 10.5 `service-controller.service: Failed to parse start command`

`services.json` has a malformed entry, usually because `id` has
uppercase or special chars. Run:

```bash
/opt/service-controller/venv/bin/python -c \
    "import sys; sys.path.insert(0,'/opt/service-controller'); from services import load_services; print(load_services())"
```

And check the printed list for typos in unit names.

### 10.6 `Invalid or corrupt sudoers file, please review`

`visudo -c -f` was not run before installing. The syntax must be
reviewed. Validate:

```bash
sudo visudo -c -f /tmp/service-controller-sudoers
```

If it fails, the file is invalid — check that every Cmnd_Alias name
spells `SVC_CTL_...` exactly as in the snippet.

### 10.7 Caddy won't reach Flask over LAN

Flask binds to `127.0.0.1` by default. Verify:

```bash
ss -tlnp | grep 8090
# Expected: 127.0.0.1:8090
# NOT 0.0.0.0:8090
```

If Caddy is the reverse proxy then nothing is reachable outside
your host — that is the intended configuration.

### 10.8 `systemctl: unknown operation ...`

The generated sudoers rule's verb list covers only `start`, `stop`,
and `restart` (see `scripts/gen_sudoers.py` lines 34–39).
`reload`, `daemon-reload`, `status`, `enable`, `disable`, and so on
are all blocked.

### 10.9 `systemctl: access denied ... try running as 'root'`

sudo is not available to the user, or the rule is malformed.
Test manually:

```bash
sudo -u service-controller sudo /usr/bin/systemctl start llama-server.service
```

### 10.10 `No such file or directory: b'python3'` when invoked manually

`python3` may be missing from `PATH` (e.g. a fresh SSH session).
Always use the venv path:

```bash
/opt/service-controller/venv/bin/python /opt/service-controller/app.py
```

### 10.11 `Cannot find file services.py` in app

The working directory in `service-controller.service` should be
`/opt/service-controller`. Verify `WorkingDirectory=` in the unit file
and confirm the file exists:

```bash
ls -l /opt/service-controller/services.py /opt/service-controller/app.py
```

### 10.12 `Failed to get service status: 'NoneType' object has no attribute 'strip'`

`systemctl` returned no fields for the unit. Likely a typo in
`services.json` — the unit name doesn't exist on this host.

Run:

```bash
systemctl list-units | grep <your-unit-name>
```

### 10.13 `HTTP Error 403: forbidden` from Flask UI

The UI is probably bound outside the reverse-proxy auth flow and
trying to hit `/api/verify` directly from a browser. Either:

- Open http://localhost:8090 (no auth) if you want to bypass PocketID
  for development, or
- Add `allow_unrestricted=true` to your Caddy file to remove PocketID.

### 10.14 `Failed to get service status: 'NoneType' object has no attribute 'strip'`

`systemctl` returned no fields for the unit. Likely a typo in
`services.json` — the unit name doesn't exist on this host. Run
`systemctl list-units | grep <name-of-unit>` and fix the entry.

### 10.15 `HTTP 403 forbidden` from Flask UI

The UI is probably bound outside the reverse-proxy auth flow and
trying to hit `/api/verify` directly from a browser. Either:

- Open http://localhost:8090 (no auth).
- Add `allow_unrestricted=true` to your Caddy file to remove
  PocketID.
